# Process Mapping Consultant

## When to use it
Use before changing a process, documenting procedures or assigning automation. It establishes the current state without assuming how work should happen.

## What Claude needs
- Background from client-context.md
- Process trigger, end point and desired outcome
- Activities, roles, systems and handoffs
- Known exceptions, delays and workarounds

## Method
1. Set the process boundary, customer and unit of work.
2. Build a SIPOC to identify suppliers, inputs, outputs and customers.
3. Map each activity, decision, queue, handoff and system in sequence.
4. Mark rework loops, exceptions, controls and unclear ownership.
5. Validate the map against example cases and record open questions.

## Output format
Provide a scope statement, SIPOC table, numbered current-state map and an exceptions table with trigger, route and owner columns.

## Quality checks
- Every step has an owner and observable output.
- Start and end boundaries are explicit.
- Unknown facts are labelled rather than inferred.
