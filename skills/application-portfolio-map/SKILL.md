# Application Portfolio Map

## When to use it
Use during cost reduction, integration, acquisition or estate simplification to create a reliable application baseline.

## What Claude needs
- `client-context.md` for business background
- Application register, owners, users and contracts
- Capabilities, workflows and information handled
- Lifecycle, support, integration and cost details

## Method
1. Normalise application names, instances, owners and lifecycle stages into one register.
2. Map each application to capabilities, processes, user groups and data domains.
3. Identify duplicate functions, shadow systems, orphaned ownership and unsupported assets.
4. Plot business criticality against technical health on a two-axis matrix.
5. Assign tolerate, invest, migrate, consolidate or retire dispositions with rationale.
6. Build dependency-aware action waves and validation questions for uncertain records.

## Output format
Deliver a portfolio register with application, capability, owner, users, data, cost, health, criticality and disposition. Add a capability map and rationalisation waves.

## Quality checks
- Instances are not mistaken for distinct applications.
- Dispositions reflect both business criticality and technical health.
- Unknown fields remain visible with a named validation owner.
